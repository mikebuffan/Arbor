# Investigation Casework Wave 3 — investigator behavior layer

Date: 2026-09-30  
Branch: `feature/research-investigation-integrity-layer-20260930`  
PR: #218  
Scope: source-only research behavior. No real Epstein/DOJ/EFTA ingestion.

## Goal

Move Arbor from pattern discovery toward sustained casework behavior:

- track who is documented as knowing what, and when;
- enforce hard timeline geometry instead of narrative smoothing;
- infer missing **functions** without inventing missing people;
- make anomalies fight strong ordinary explanations;
- preserve document-version drift;
- reconstruct decisions from the information available at the time;
- detect recurring role/action mismatches;
- distinguish contemporaneous from retrospective evidence without turning timing into a credibility score;
- run isolated analytic lenses in parallel;
- keep competing case theories alive until evidence kills them;
- collapse dependent anomalies so one upstream error cannot masquerade as ten independent oddities;
- distinguish cross-purpose document convergence from several files generated by one workflow;
- automatically ask "why now?" around material changes.

## 1. Knowledge-state ledger

`investigationKnowledgeState.ts` records the earliest **documented** evidence that a subject possessed or could access a specific fact.

It can distinguish:

- knowledge documented before an action;
- an action that predates the earliest documented knowledge;
- no documented knowledge record in the supplied scope.

The latter two create information-path questions only. They never assert mind-state, secret knowledge, or improper access.

## 2. Hard timeline geometry

`investigationTemporalConstraints.ts` evaluates bounded event windows against minimum transition times.

A conflict is "hard" only if **no placement inside the documented windows** could satisfy the constraint.

A hard conflict identifies incompatible bounds. It does not decide which record is wrong or why.

## 3. Missing-function inference

`investigationMissingFunction.ts` creates anonymous placeholders such as `UNKNOWN_FUNCTION_*` when a documented transition requires a capability that is not represented in the current graph.

It infers:

- required capability;
- upstream/downstream nodes;
- primary-record search targets;
- a direct/no-intermediary alternative.

It never invents or identifies a person to fill the gap.

## 4. Ordinary-explanation adversary

`investigationMundaneAdversary.ts` uses canonical Arbor to produce the strongest plausible boring explanations for an anomaly:

- administrative;
- clerical;
- routine legal/procedural;
- logistical;
- coincidental;
- ordinary role behavior.

Every ordinary explanation must predict evidence and name falsifiers.

The engine is explicitly told not to weaken boring explanations merely to protect an exciting hypothesis.

## 5. Version drift

`investigationVersionDrift.ts` compares releases of the same document across:

- content SHA-256;
- page count;
- structured fields;
- release chronology.

Changes are preserved as version history and research questions. A changed release is never automatically labeled tampering.

## 6. Decision provenance

`investigationDecisionProvenance.ts` separates:

- information documented as available before a decision;
- information first documented later;
- cited basis available before the decision;
- cited basis not found in the documented pre-decision information state.

This prevents hindsight from being silently backdated into an institutional decision.

## 7. Role/action mismatch

`investigationRoleMismatch.ts` compares recurring documented actions with a source-backed role baseline.

An out-of-role action becomes interesting only when it recurs across the configured independent-lineage threshold.

It creates a "what function was this person actually performing?" question, not a misconduct claim.

## 8. Evidence temperature

`investigationEvidenceTemperature.ts` labels evidence as:

- contemporaneous;
- near-contemporaneous;
- retrospective;
- undated.

Temporal distance is metadata for reasoning. It is explicitly **not** a standalone truth/credibility score.

## 9. Parallel blind lenses

`investigationParallelReconstruction.ts` compares isolated reconstructions produced from different analytic lenses:

- chronology;
- money;
- logistics;
- relationships;
- institutional response.

Cross-lens convergence means different reasoning frames arrived at the same event interpretation. It does **not** create new evidentiary independence when the lenses use the same underlying records.

## 10. Competing case theories

`investigationCompetingTheories.ts` keeps multiple theories alive simultaneously.

Theory states are:

- active;
- weakened by contradiction/unexplained evidence;
- falsified by required prediction failure.

The ledger never chooses a "winner" merely because one theory currently has more supporting references.

## 11. Anomaly dependency tree

`investigationAnomalyDependencies.ts` records when one anomaly depends on another.

If eight downstream weird edges all derive from one bad identity merge, they remain eight observations but only one upstream root signal.

Cycles are rejected because a circular anomaly explanation has no trustworthy root.

## 12. Document-family collision

`investigationDocumentFamilyCollision.ts` distinguishes convergence across records created for genuinely different purposes from several records generated by one administrative workflow.

Examples of different purposes might include:

- scheduling;
- accounting;
- land registry;
- travel operations;
- court process.

Cross-purpose convergence strengthens an event lead, but does not establish conduct or causation.

## 13. "Why now?" windows

`investigationWhyNow.ts` takes a material event and inspects a bounded window before and after it.

It asks:

- what changed immediately before;
- what happened immediately after;
- which nearby events have independent provenance;
- what ordinary process could explain the timing;
- what downstream event would be expected if the focal event actually caused something.

Temporal proximity generates questions, never causation.

## Controller behavior

The canonical Arbor research controller now carries explicit rules for every Wave 3 method.

These rules sit **after** the existing integrity/discovery/prediction rules, so casework remains subordinate to provenance and finding-promotion gates.

## Current boundary

Wave 3 is source logic and tests. It is not permission to:

- ingest real Epstein/DOJ/EFTA material;
- infer private-person identities;
- apply database migrations;
- enable a live casework worker;
- schedule unattended research;
- publish findings.

Where a method would eventually require durable source-backed structured inputs, live wiring remains a separate gate.
